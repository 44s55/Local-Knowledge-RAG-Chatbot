# Local-Knowledge-RAG-Chatbot 本地知识库问答系统

📖 项目介绍
本项目是一套轻量、完整、可落地的本地知识库 RAG 问答系统，基于 Chroma 向量数据库 + 阿里通义 DashScope Embedding/LLM 实现。实现了从文档解析、文本切片、向量化存储、多路混合检索、大模型问答、答案溯源的完整端到端 RAG 流程，配套 Gradio 可视化网页交互界面，开箱即用。

新增轻量化智能Agent调度层，基于Prompt驱动实现意图识别与工具自动调度，区分知识库查询与闲聊场景，优化响应效率与使用体验；支持SSE流式逐字输出，带来打字机式交互体验；前端同步展示Agent决策过程与检索溯源详情，全流程可观测。

现已升级为 **FastAPI 后端 + Gradio 前端的前后端分离架构**，通过 HTTP 接口解耦业务逻辑与交互层，具备更好的扩展性与部署灵活性；配套Windows一键启动脚本，脱离开发环境即可运行。

项目全程解耦模块化开发，代码规范贴合企业级工程标准，可直接作为简历实战项目、毕设项目、面试口述项目。

🚀 技术栈
- 后端框架：FastAPI + Uvicorn，标准化 RESTful 接口
- 流式协议：SSE（Server-Sent Events）服务端推送，实现打字机式流式问答
- 交互界面：Gradio 4.x 可视化网页端，支持文件上传、参数调节、溯源展示、Agent决策可视化
- 智能调度层：轻量化Prompt驱动Agent，原生实现意图识别与工具路由，无第三方Agent框架依赖
- 向量数据库：Chroma（本地持久化向量库，轻量免部署）
- Embedding 模型：阿里 DashScope text-embedding-v2（1536维向量）
- 大模型服务：通义千问系列（OpenAI 兼容接口调用）
- 稀疏检索：rank-bm25 Okapi 实现关键词召回
- 融合算法：RRF倒数排名融合算法，解决多路检索分数量级不一致问题
- 重排服务：qwen3-rerank 云端精排接口，可通过前端开关动态开启
- 开发环境：Python3.10 + Conda 虚拟环境
- 部署架构：前后端分离，支持独立部署、横向扩展
- 代码规范：模块化解耦、全局单例复用、参数统一配置、日志优化、异常捕获

🎯 项目核心功能
- 多格式文档加载：支持 TXT / PDF / MD 文档解析读取
- 智能语义切片：按字符长度分割，支持自定义切片大小与重叠量
- 文本向量化：调用阿里通义向量模型，生成 1536 维语义向量
- 向量持久化存储：基于 Chroma 实现本地向量库持久化，断电不丢失数据
- 多路混合检索：BM25关键词稀疏检索 + 向量稠密语义检索，RRF倒数排名融合，同时兼顾专有名词召回与语义理解
- 智能Agent调度：自动识别用户提问意图，知识库类问题走RAG检索链路，闲聊/计算类问题直接返回，减少无效检索，提升响应效率
- 幻觉抑制机制：向量距离阈值判断，知识库无匹配内容时直接拦截拒绝回答，禁止模型编造内容；同时配合 System 提示词强约束双重兜底
- 多轮对话记忆：内置 ConversationMemory 模块，控制最大对话轮次，支持连续上下文问答
- SSE流式问答：支持服务端推送流式输出，回答逐字渲染，提升长文本交互体验
- Agent决策可视化：前端实时展示Agent思考过程与工具选择结果，全链路透明可观测
- 答案溯源能力：返回答案对应的文档来源、相似度距离分数、重排分数、内容片段预览，可溯源校验答案准确性
- 标准化后端接口：RESTful 风格接口，支持第三方系统对接
- Gradio 网页交互：可视化操作界面，支持文档上传入库、检索参数调节、重排开关、一键清空对话、一键清空全部知识库
- Windows一键启动：提供bat批处理脚本，双击即可启动前后端服务，无需命令行操作
- 工程优化：屏蔽 Chroma / Gradio 遥测报错、全局检索器单例复用、路径适配、环境隔离、API调用全链路异常捕获兜底
- 预留扩展：重排模块接口预留，可快速开启云端精排能力

📊 整体架构流程

文档入库流程：
前端上传文件 → 后端接口接收 → 清洗文本 → 语义切片 → Embedding 向量化 → Chroma 向量库持久化存储 → 构建BM25稀疏检索索引

用户问答流程：
前端提交问题 → 后端接收请求 → 轻量化Agent意图识别 → 工具路由
    ├─ 知识库查询 → BM25关键词检索 + 向量相似度检索 → RRF倒数排名融合 → Reranker精排 → 召回知识库上下文 → 拼接约束Prompt → LLM流式生成回答 → SSE逐帧推送
    └─ 闲聊/常识问题 → LLM直接回答
→ 后端封装返回回答 + 溯源来源 + Agent决策 → 前端打字机效果渲染 + 全信息展示

⚙️ 环境部署与启动

1. 环境依赖安装
基于 conda 创建虚拟环境，安装项目全部依赖
```bash
conda create -n llm_env python=3.10
conda activate llm_env
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

2. 环境变量配置
根目录复制 `.env.example` 为 `.env`，配置阿里通义密钥与模型地址
```env
DASHSCOPE_API_KEY=你的密钥
LLM_MODEL=qwen-turbo
VECTOR_DB_PATH=./chroma_db

# 服务端口配置
FASTAPI_HOST=0.0.0.0
FASTAPI_PORT=8000
GRADIO_PORT=7860
```

3. 启动后端服务
```bash
python main_fastapi.py
```
启动成功后接口文档地址：`http://127.0.0.1:8000/docs`

4. 启动前端页面
新开终端，激活同一虚拟环境：
```bash
python web_gradio.py
```
启动成功后浏览器访问：`http://127.0.0.1:7860`

5. Windows一键启动（推荐）
无需打开命令行，在项目根目录按顺序双击脚本即可：
    1. 先双击「启动后端.bat」，等待控制台输出服务启动成功，保留窗口
    2. 再双击「启动前端.bat」，等待页面启动，自动打开浏览器或手动访问地址

6. 操作流程
    1. 左侧面板上传 PDF/TXT/MD 文档，点击「保存文件到data目录并入库」，自动完成切片、向量化、构建BM25索引
    2. 右侧输入框输入问题，回车发送，获取流式回答、Agent决策过程与检索溯源详情
    3. 可通过 Top-K 滑块调节检索返回片段数量
    4. 可勾选「开启Reranker重排」开关，启用云端精排提升召回质量
    5. 支持清空对话会话、一键清空全部知识库

🔌 后端核心接口

| 接口路径 | 请求方法 | 功能说明 |
|----------|----------|----------|
| `/upload` | POST | 上传文档并解析入库，支持 PDF/TXT/MD |
| `/chat` | POST | 知识库问答接口，支持传入对话历史、检索参数 |
| `/chat/stream` | POST | 流式知识库问答接口（SSE），逐字返回回答内容 |
| `/clear_history` | POST | 清空服务端对话上下文 |

🧪 功能测试用例
1. 文档入库测试：上传PDF文档，终端输出切片数量、入库成功、BM25索引重建完成
2. 正常问答测试：提问文档内知识点，正常返回答案，溯源面板展示来源文件、向量距离、片段内容
3. 流式输出测试：提问后回答逐字打字机式渲染，而非一次性全部显示
4. Agent决策可视化测试：提问后前端Agent面板展示思考原因与选择工具，控制台同步输出决策日志
5. 幻觉拦截测试：提问知识库不存在的内容，触发阈值拦截，返回「知识库未查询到相关内容」
6. 清空对话测试：点击「清空对话会话」，聊天记录清空，知识库数据保留，可继续提问
7. 清空知识库测试：点击「清空全部知识库」，向量库与BM25索引全部清空，聊天记录保留；再次提问触发拦截；重新上传文档恢复功能
8. Agent调度测试：提问知识库内专业问题，控制台输出选择knowledge_search工具，返回带溯源的回答；提问闲聊/常识问题，控制台输出选择no_tool工具，直接返回回答，无检索溯源
9. 重排功能测试：勾选重排开关后提问，溯源面板展示重排分数，片段顺序按语义相关性重新排序
10. 接口联调测试：访问 `/docs` 接口文档，在线调试上传、问答、流式接口，返回符合预期的JSON格式
