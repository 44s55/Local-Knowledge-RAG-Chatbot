## 📊 整体架构流程

**文档入库流程：**
前端上传文件 → 后端接口接收 → （ZIP包自动解压） → 清洗文本 → 语义切片 → Embedding 向量化 → Chroma 向量库持久化存储 → 构建BM25稀疏检索索引

**用户问答流程：**
前端提交问题 → （密码校验） → 后端接收请求 → （多知识库路由） → Agent意图识别 → 工具路由
  ├─ 知识库查询 → 查询优化（改写/多查询扩展） → BM25关键词检索 + 向量相似度检索 → RRF倒数排名融合 → 结果去重排序 → 上下文压缩 → Reranker精排（可选） → 召回知识库上下文 → 拼接约束Prompt → LLM流式生成回答 → SSE逐帧推送
  └─ 闲聊/常识/计算类问题 → 对应工具执行 / LLM直接回答 → 后端封装返回回答 + 溯源来源 + Agent决策 → 前端打字机效果渲染 + 全信息展示

**LangChain Agent调度流程：**
用户输入 → Function Calling工具匹配 → 调度对应工具执行（RAG检索/计算器/时间查询） → 工具结果返回 → 大模型整合答案 → 输出最终结果；支持单轮多工具调用、复合问题自动拆解。

## ⚙️ 环境部署与启动

### 方式一：Windows Conda 本地开发环境

1. **环境依赖安装**
基于 conda 创建虚拟环境，安装项目全部依赖
```bash
conda create -n llm_env python=3.10
conda activate llm_env
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

2. **环境变量配置**
根目录复制 `.env.example` 为 `.env`，配置阿里通义密钥与模型地址
```env
DASHSCOPE_API_KEY=你的密钥
LLM_MODEL=qwen‑turbo
VECTOR_DB_PATH=./chroma_db

# 服务端口配置
FASTAPI_HOST=0.0.0.0
FASTAPI_PORT=8000
GRADIO_PORT=7860

# 访问密码（留空则不启用密码验证）
ACCESS_PASSWORD=
```

3. **启动后端服务**
```bash
python main_fastapi.py
```
启动成功后接口文档地址：`http://127.0.0.1:8000/docs`

4. **启动前端页面**
新开终端，激活同一虚拟环境：
```bash
python web_gradio.py
```
启动成功后浏览器访问：`http://127.0.0.1:7860`

5. **LangChain Agent 全链路测试**
```bash
python agent_demo.py
```
内置数学计算、时间查询、知识库检索、多工具混合四组测试用例，一键验证Agent与RAG全链路调度能力。

6. **Windows一键启动（推荐）**
无需打开命令行，在项目根目录按顺序双击脚本即可：
  1. 先双击「启动后端.bat」，等待控制台输出服务启动成功，保留窗口
  2. 再双击「启动前端.bat」，等待页面启动，自动打开浏览器或手动访问地址

7. **操作流程**
  1. 左侧面板上传 PDF/TXT/MD/ZIP 文档，点击「保存文件到data目录并入库」，自动完成切片、向量化、构建BM25索引
  2. 右侧输入框输入问题，回车发送，获取流式回答、Agent决策过程与检索溯源详情
  3. 可通过 Top‑K 滑块调节检索返回片段数量
  4. 可勾选「开启Reranker重排」开关，启用云端精排提升召回质量
  5. 可勾选「开启 查询改写」，自动优化口语化/模糊问题，提升检索匹配效果
  6. 可勾选「开启 多查询扩展」，生成多组查询并行检索，扩大召回覆盖面
  7. 可勾选「开启 上下文压缩」，精炼检索片段，去除冗余信息，提升回答精准度
  8. 支持清空对话会话、一键清空全部知识库
  9. 可通过多知识库管理面板创建、切换、删除不同主题知识库

### 方式二：Docker Compose 容器化部署

>一套代码同时支持：Windows本地Conda开发环境 / Docker容器生产环境

#### 文件说明
- `Dockerfile`：镜像构建脚本
- `docker‑compose.yml`：容器编排配置
- `.env`：本地开发环境变量（conda环境使用）
- `.env.docker`：容器内部使用环境变量
- `.dockerignore`：过滤虚拟环境、向量库、缓存，减小镜像体积

#### 容器启动步骤
1. 修改 `.env.docker`，填入你的DashScope API密钥
2. 构建镜像
```bash
docker compose build
```
3. 后台启动服务
```bash
docker compose up -d
```
4. 查看运行日志
```bash
docker compose logs -f
```
5. 停止容器
```bash
docker compose down
```

>💡重要说明：
1. 使用volume挂载`chroma_db`向量库目录，删除容器知识库数据不会丢失
2. 环境变量文件通过挂载方式注入容器，**API密钥不会打包进镜像，避免密钥泄露**
3. 本地开发依然使用`conda activate llm_env`调试，Docker用于服务部署

7. 清空知识库测试：点击「清空全部知识库」，向量库与BM25索引全部清空，聊天记录保留；再次提问触发拦截；重新上传文档恢复功能
8. Agent调度测试：提问知识库内专业问题，控制台输出选择knowledge_search工具，返回带溯源的回答；提问闲聊/常识问题，控制台输出选择no_tool工具，直接返回回答，无检索溯源
9. 重排功能测试：勾选重排开关后提问，溯源面板展示重排分数，片段顺序按语义相关性重新排序
10. 接口联调测试：访问 `/docs` 接口文档，在线调试上传、问答、流式接口，返回符合预期的JSON格式
11. 查询改写测试：勾选查询改写开关，提问口语化问题（如“这东西啥意思”），控制台输出改写后的标准查询，检索结果匹配度提升
12. 多查询扩展测试：勾选多查询扩展开关，控制台输出生成的多组查询，召回的文档片段数量更多、覆盖角度更广
13. 上下文压缩测试：勾选上下文压缩开关，溯源面板展示的片段内容更精炼，无关信息被过滤
14. LangChain Agent多工具调度测试：运行agent_demo.py，依次验证数学计算、时间查询、知识库检索三类独立场景，Agent自动调度对应工具并返回正确结果
15. 多工具混合任务测试：提问同时包含知识库查询与数值计算的复合问题，Agent自动拆解问题，分别调用对应工具，最终整合输出完整答案
16. 多知识库管理测试：创建多个知识库，切换后上传文档，验证各知识库数据独立不互通；删除知识库后验证数据清除
17. 访问密码测试：配置访问密码后刷新页面，自动跳转登录页；密码正确进入系统，错误提示验证失败
18. ZIP批量上传测试：打包多个文档为ZIP上传，验证自动解压、全部入库、重复文件自动跳过
19. 满意度反馈测试：回答后点击点赞/点踩按钮，验证反馈成功提交，本地feedback.json文件更新
20. 引用对应测试：提问后验证回答中的引用编号与溯源面板的[编号]一一对应，可快速定位来源

## 💡 项目亮点（面试专属口述）

- 前后端分离架构：业务逻辑与交互层解耦，后端标准化接口可对接多端，前端可独立迭代替换
- 双Agent架构：同时提供轻量化原生Agent与LangChain标准Agent两种实现，兼顾极致轻量化与标准生态兼容性
- 原生Agent实现：纯手写Prompt驱动智能调度，不依赖LangChain等高层Agent框架，完整实现「思考‑决策‑执行」闭环，轻量化易扩展
- LangChain标准Agent：基于Function Calling机制实现工具注册与调度，RAG主链路作为标准工具无缝接入，复用全部检索优化能力
- 多工具混合调度：支持知识库检索、数学计算、时间查询等多工具协同，自动拆解复杂复合问题，扩展系统能力边界
- 三级检索优化体系：查询改写+多查询扩展+上下文压缩，从输入、召回、输出三个环节全面优化检索效果，全开关可控，兼顾效果与成本
- 可插拔模块化设计：所有优化能力独立封装，参数开关控制，默认向下完全兼容，不影响基础模式运行
- 全链路效果可观测：优化过程全日志输出，前端可通过溯源面板直观对比优化前后的片段差异
- 流式交互体验：基于SSE协议实现服务端推送，回答逐字渲染，大幅提升长文本等待体验，接近主流大模型产品交互感
- 全链路可观测：前端同步展示Agent决策过程、检索溯源详情、相似度与重排分数，问题排查与效果验证清晰透明
- 解决大模型幻觉：通过向量距离阈值硬拦截 + 强Prompt约束双重机制，严格限制模型仅使用已知知识库内容作答
- 混合检索优化：BM25 Okapi关键词检索搭配向量检索，RRF倒数排名融合，改善专有名词、专业术语召回效果
- 统一数据格式：向量检索、BM25检索输出结构统一，上层业务无需做类型兼容，代码健壮性高
- 语义切片优化：固定长度+重叠量切片，分批向量化规避接口调用上限，提升入库稳定性
- 性能优化：检索器全局单例初始化，避免重复加载向量库，减少资源开销
- 可溯源设计：问答结果附带文档来源、相似度分数与重排分数，引用编号一一对应，方便问题排查与答案校验
- 多知识库物理隔离：独立向量目录+独立索引，按业务维度拆分数据，权限与边界清晰
- 轻量权限管控：零依赖配置化密码验证，内网部署快速启用安全防护，无需额外组件
- 批量运维能力：ZIP批量上传自动解压去重，大幅提升大批量文档入库效率
- 闭环运营体系：满意度反馈收集持久化，支撑后续效果迭代与bad case分析
- 工程健壮性：完善异常捕获、空内容兜底、统一日志体系、自定义异常类、屏蔽第三方库冗余报错
- 低耦合高扩展：各模块独立封装，抽象基类定义接口，可无缝替换本地模型、不同向量库、不同LLM服务
- 产品化交互：Gradio 可视化网页端，零命令行操作即可完成文档入库、问答、知识库管理全流程
- 开箱即用：提供Windows一键启动脚本，脱离开发环境与命令行即可快速部署运行
- 容器化工程能力：Docker Compose一键部署，区分两套环境变量；Volume挂载持久向量数据；密钥挂载注入镜像，杜绝密钥泄露风险
- 工程化规范：统一配置管理、环境变量隔离、错误码标准化，符合企业级后端开发规范
